# QuietDesk

一个用于 macOS 14 及更新版本的原生远程桌面应用，使用 ScreenCaptureKit 与 H.264 控制带宽。文件和文件夹复制需要接收端确认，文字与图片自动同步。支持全屏悬浮设置、连接状态浮层、自定义应用图标、连接中调画质、断线重连、登录后台共享、快捷连接记录与 Caps Lock 操作。两台 Mac 使用同一个应用：家里选择“共享这台 Mac”，公司选择“连接家里 Mac”。使用现有的 TCP 端口映射，不依赖中转服务或账号。

[下载最新版安装包](https://github.com/nXiaoK/QuietDesk/releases/latest) · [查看构建状态](https://github.com/nXiaoK/QuietDesk/actions) · [MIT 许可证](LICENSE)

## 使用

1. 从 Releases 下载 DMG，打开后将 QuietDesk 拖到“应用程序”；也可以下载 ZIP 解压后移动应用。两台 Mac 都安装。首次运行若被系统拦截，在“系统设置 → 隐私与安全性”中允许打开自己信任的应用。自动构建使用本地临时签名，未经过 Apple 公证；也可以在各自机器上从源代码构建。
2. **家里 Mac**：打开应用，切换到“共享这台 Mac”。授予**屏幕录制**和**辅助功能**权限；屏幕录制授权后，完全退出并重新打开应用。辅助功能未授权时只可观看。0.6.1 的双方可以在系统授权真正生效后更新控制状态，不必断开视频或文件传输；较旧控制端需要重新连接。
3. 选择显示器，监听端口默认 `5908`。将你已有的**外部 TCP 端口**映射到这台 Mac 的此端口。点击“开启共享”。如系统防火墙询问是否允许传入连接，允许此应用。
4. 复制家里 Mac 的配对码，通过自己的可信渠道传到公司 Mac。配对码等同于控制凭证，避免发到公开聊天或日志。它使用 256 位随机数，保存在家里 Mac 的钥匙串。停止共享后可重新生成，使旧码失效。
5. **公司 Mac**：填写家里域名或 IP、**外部映射端口**和完整配对码，点击“连接”。地址不包含 `http://`。IPv6 地址直接填写，不加方括号，端口单独填写。
6. 点击画面后操作远端，按 **Control + Option + Escape（⌃⌥Esc）**释放键盘鼠标。开启双向剪贴板后，控制端只在 QuietDesk 位于前台时读取并发送本机的新复制；远端的新复制在控制端释放远程画面焦点、回到本机操作时读取并发送。完整的焦点节流需两端都安装支持此功能的新版。复制文件时，在接收端点击“接收”，下载完成后再粘贴。“发送文字 / 获取文字”仍保留为手动文字同步入口，手动入口单次最大 1 MB。
7. 在公司 Mac 点击窗口工具栏的**画质与连接**，连接中即可调整画质；全屏时点击右侧圆形按钮进入相同设置。两端都需升级到 0.4.0。

家里 Mac 必须已经登录，并保持应用运行。共享时应用暂时防止空闲睡眠；停止共享或退出后恢复系统原有设置。应用不修改端口映射或系统录屏权限；登录项只在你操作登录自启开关时注册或取消。

## 断线重连与快捷连接

公司 Mac 默认开启“断线自动重连”。在窗口工具栏的“画质与连接”或全屏右侧悬浮面板中可以关闭。网络中断后依次等待 **1、2、4、8、16、30 秒**重试，之后保持 30 秒间隔；稳定连接 30 秒后重置间隔。点击“断开”或退出应用会取消后续重试。协议错误与可识别的认证错误不会反复重试。

这版将视频解码与窗口显示分开：窗口最小化或切到后台时仍可解码并确认帧，只保留最新解码画面。收包时按实际收到的字节更新活动时间，避免大消息尚未收齐就被当作失联。真正超过 30 秒没有任何接收数据时重建连接；编码或视频确认超过 90 秒无进展也会重新建立会话。这些修正针对发现的超时路径，不代表已经定位用户真实网络中的全部断开原因。

画质与连接设置会显示“上次断开”的时间和原因。若仍频繁掉线，请提供这里的错误信息，便于区分网络、TLS、采集与解码问题。TCP 本身会重传丢失的数据，应用不会将单次丢包直接当成断开。

成功建立会话后自动保存地址、端口、设备名称和连接时间，配对码独立保存在 macOS 钥匙串。重启后通过最近连接卡片连接，不需要再次输入配对码。记录没有数量限制；连接页展示最近两条，“管理记录…”中可查看并连接全部记录，也可移除记录及对应钥匙串配对码。旧版没有保存完整历史和客户端配对码，升级后首次成功连接会建立记录。

## 登录后自动启动与后台共享

在家里 Mac 的“共享这台 Mac → 后台与登录启动”中设置：

1. 建议将应用先放入“应用程序”文件夹，确认录屏与辅助功能权限、监听端口、显示器和配对码正常。
2. 开启“登录后自动启动 QuietDesk”。应用使用 macOS 的登录项接口；如系统要求批准，点击设置中的按钮前往“登录项”允许。
3. 开启“启动后自动开启共享”。之后手动启动或登录启动都会切到共享模式并尝试开启共享。
4. 保持“登录自动启动时最小化窗口”开启。此选项只影响系统登录启动；手动打开时仍可显示窗口。

监听端口、显示器和画质设置会保存。若监听或显示器暂时不可用，会按间隔重试；首次缺少权限时显示未启动原因，需要先完成授权。系统菜单栏有 QuietDesk 图标，可以打开窗口、开启/停止共享或退出。共享时关闭窗口仍保持后台运行；真正退出应用会停止共享。

显示器列表随系统变化自动刷新。原选择仍可用时保留；失效后优先选择当前主显示器，主显示器不可采集时选择首个可用显示器。没有可用显示器时保留记录并等待重试。共享期间，所选显示器被移除、实际像素尺寸或桌面位置/缩放发生变化，会释放输入并重新准备共享；控制端开启自动重连时会恢复连接。其他显示器变化不会单独打断会话，旧显示器重新接入也不会强制切回。

自启发生在用户登录后，不能跨过 FileVault 解锁或登录窗口。如果从系统录屏菜单主动停止共享，本次运行不会自动恢复共享；再次启动应用仍遵循已保存的启动设置。本地临时签名应用更新后，系统可能要求重新授权或重新批准登录项，建议离开家前实际验证一次。

## 双向复制粘贴

两端默认开启“同步文字、图片和文件”，任一端关闭即停止同步。纯文字与 PNG 图片（TIFF 会转换为 PNG）继续自动同步。普通文件和文件夹需要**接收端逐次确认**，双向均如此：

1. 在一端复制文件或文件夹，应用先在本机整理文件元信息，只向另一端发送名称预览、数量和总大小，不传输文件内容。名称预览最多显示前三项，完整文件数量和大小照常统计，不限制实际选择数量。
2. 接收端弹出“接收文件”窗口。点击**“接收”**才请求文件数据并开始下载；点击**“拒绝”**、按 Escape 或关闭弹窗都会取消本次接收，保留原有系统剪贴板。
3. 等待显示接收完成后，在目标应用中粘贴。公司 Mac 向家里 Mac 复制文件时，确认窗口显示在家里 Mac，可在远程画面中点击。

等待确认时不会创建接收文件，不会自动接受。请求沿用约 90 秒超时；重新复制其他内容、关闭同步或断开连接会取消对应待办，旧弹窗的回复不能启动新请求。拒绝后不会因剪贴板轮询重复弹窗；需要时重新复制，或在远程画面再次按 ⌘V 发起一次新的文件请求。

文件按 **32 KB** 分块并逐块确认，文件 I/O 在后台执行，控制消息可以在分块之间传递。没有人为设置文件总大小上限，但受磁盘容量、可读权限、网络速度和往返延迟影响。状态区和全屏进度提示会显示准备、收发字节数和完成状态。

- 从公司 Mac 粘贴文字或图片到远端时，远程画面中的 **⌘V / ⌘⇧V** 会先等待同步完成再发送粘贴按键。等待期间若焦点离开或继续点击、输入，会取消这次延迟粘贴。**文件不会保留延迟粘贴动作**，请确认接收并等待传输完成后再按一次 ⌘V，避免弹窗关闭后粘贴到错误窗口。
- 从远端复制大文件后，先等公司 Mac 显示“接收完成”，再到本机 Finder 等应用粘贴。尚未完成时，本机系统剪贴板仍保留原内容；应用不会拦截其他本机应用的粘贴快捷键。
- 接收完成之前不会发布半成品文件。开始读取前及读完后校验源文件类型、大小和修改时间；等待确认或复制期间源文件变化、磁盘写入失败、断线或取消会中止该次传输。连接重建后请重新复制未完成的文件，不支持文件断点续传。
- 使用会话、内容标记和修订顺序抑制重复回传；双方同时复制时按修订顺序收敛，避免互相回写。
- 完成的文件位于 `~/Library/Application Support/QuietDesk/Clipboard/received/`，可以从画质与连接设置或共享页打开目录。文件会保留到你自行清理，清理后原剪贴板文件引用将失效。正常断线会清理未完成数据；强退或断电可能在同级 `partial` 目录留下缓存。
- 暂不复制符号链接、设备等特殊文件；遇到时会说明原因，可以先压缩为 ZIP 再复制。普通权限和修改时间会保留，不复制完整 ACL 或扩展属性；需要完整文件系统元数据时也请压缩后传输。

同步只捕获连接建立后的新复制内容；连接前已复制的内容可以通过远程 ⌘V 发起同步，文件仍需对端确认。自动同步按控制端焦点节流：控制端的 QuietDesk 不在前台时，不读取本机剪贴板内容；重新进入前台后只发送期间最新的一次复制。操作远程画面时，远端暂不读取新复制；释放远程控制、点击本机控件或切换本机应用后，远端发送最新复制。已经开始的传输、已接受的文件及确认回复继续完成，等待粘贴期间离开画面焦点仍不会执行迟到的 ⌘V。手动“发送文字 / 获取文字”继续按点击执行。

建议**两端都安装支持焦点节流的新版**。新版连接旧版时仍兼容原协议，但旧版远端不会识别焦点偏好，无法限制它在远端读取和发送剪贴板；控制端自身的前台读取限制仍生效。文件确认需两端支持 0.5.0 引入的流程：新版不向未声明支持文件确认的旧接收端发送文件，界面提示升级；新版接收端也会拦截旧发送端的文件请求，在确认前不回复拉取许可。更旧的不支持自动剪贴板的版本仍可使用手动文字同步。

## 全屏与 Caps Lock

**全屏**：点击窗口工具栏的“全屏”，或按 **Control + Command + F（⌃⌘F）**进入/退出。macOS 绿色窗口按钮也可以进入全屏。全屏时隐藏连接栏和状态栏，画面保持比例，不裁剪，不显示控制状态的蓝色边线；右侧只保留一个圆形悬浮按钮。窗口模式仍保留控制焦点描边。**点击**才展开全部配置和操作，包括画质、剪贴板、重连、Caps Lock、发送/获取文字、退出全屏及断开；再次点击圆形按钮或面板右上角的关闭按钮收起。鼠标移动到顶部不会自动弹出工具条。打开配置时释放远程控制，操作完成后点击远程画面继续控制。⌃⌘F 保留给本机窗口；普通 Escape 仍可用于远端编辑器。⌃⌥Esc 释放远端控制。

在悬浮设置或普通窗口的画质与连接设置中开启**“全屏显示连接状态”**，左上角会显示延迟、实际视频分辨率、视频 FPS 和收发流量。此选项默认关闭并记住选择；状态浮层不拦截鼠标操作。延迟为加密连接上的网络往返时间（RTT），约每 5 秒更新，不是屏幕到屏幕的总延迟。无样本、样本超过 15 秒未更新或对端版本较旧时显示“—”。FPS 是实际收到的视频帧率，静止桌面可能为 0；流量包含剪贴板及应用消息。

**Caps Lock**：两台 Mac 使用 0.2.0 或更新版本，在公司 Mac 点击连接页的“Caps Lock 设置…”、会话工具栏的 Caps Lock 图标或全屏面板的“Caps Lock 转发”，先为 QuietDesk 授予**辅助功能**与**输入监控**权限，然后启用“Caps Lock 转发”。输入监控授权后可能需要完全退出并重新打开应用。家里 Mac 仍需要辅助功能权限。

- 短按后松开：在家里 Mac 已启用的中文输入法和 ASCII 英文键盘之间切换。优先恢复本会话上一次使用的中文、英文输入源。
- 按住至少 **0.6 秒后松开**：切换远端大写锁定。在大写已锁定时，短按先解除大写，不同时切换输入法。
- 仅当远程画面获得键盘焦点时生效；切换应用、释放控制、断开或拔出键盘，会取消尚未完成的长按判断。设置面板与输入框获得焦点时不捕获 Caps Lock。
- 大写状态在远端维护，不使用公司 Mac 传来的 Caps Lock 标志决定大小写。键盘上的实体指示灯不保证与远端大写状态同步，以应用反馈和远端输入结果为准。
- 输入法切换通过 macOS 输入源接口完成，不修改系统快捷键，也不自动添加或启用输入法。家里 Mac 需要已启用中文输入源和 ABC/US 等 ASCII 键盘；缺少时应用显示原因，连接继续可用。第三方输入法内部的中英文模式由该输入法决定，需实机验收。
- 该选项首次默认关闭，启用后记住选择。未启用时保留原有 Caps Lock 键码转发方式。新客户端连接旧主机时不会发送新键盘动作，会提示升级；旧客户端连接新主机也保留原有输入行为。

## 权限已勾选却未生效

从 QuietDesk 打开屏幕录制、辅助功能或输入监控设置时，屏幕底部会同时出现权限引导面板。把面板中的应用图标拖进系统权限列表，再**手动打开开关**；系统页面不接受拖入时，使用「+」选择面板显示的当前应用，或点击「在访达中显示」后从访达拖入。没有「+」的页面按系统提示在现有列表中开启。

面板提供的是真正运行中的 `.app` 文件和图标，显示完整路径及该项权限的实际状态。它会留在系统设置上方并每 2 秒刷新，也可点击「重新检测」或关闭面板；面板不抢系统设置的键盘焦点，不代替用户操作系统设置或授予权限。通过 `swift run` 等方式直接运行可执行文件时，会提示当前不是 `.app`，不提供虚假的应用拖拽；请先打开打包后的应用。

0.6.1 会显示系统接口实际返回的屏幕录制、辅助功能及输入监控状态。打开系统设置授权后，返回应用会重新检测；连接期间及启用 Caps Lock 时也定期检查。两端均为 0.6.1 时，家里 Mac 的辅助功能变化会通过当前连接同步到控制端，旧版控制端仍需重连。

Caps Lock 开关表示希望启用，状态文字另外说明监听是否真正启动。权限暂时不可用或监听失败不会清除你的开关选择；权限恢复后会尝试启动。系统显示允许但监听仍失败时，点击“重新检测”，或完全退出再打开，避免持续尝试添加同一条目。旧监听的延迟失败回调不能关闭已经重新建立的监听。

如果设置里已经勾选，但应用仍显示“未生效”：

1. 从 QuietDesk 菜单选择退出，包括菜单栏后台进程；将新版固定安装到 `/Applications/QuietDesk.app`，从此位置打开。
2. 对照应用显示的“当前应用”路径，确认系统设置中添加的是正在使用的这一份，不是下载目录、磁盘镜像或旧副本。
3. 升级后授权记录失效时，退出应用后移除旧条目并重新添加当前应用一次，允许后重开。若授权实际已生效，只是旧版会话仍仅观看，重新连接即可，不必重复添加。

本次改进权限刷新与监听恢复，不会重置系统隐私数据库或代用户授权。当前临时签名的应用识别要求随二进制哈希变化，跨版本仍可能需要重新授权。长期需要保持签名身份稳定：正式分发推荐 Developer ID Application；自用也可评估固定自签名证书，但它不提供 Apple 公证，具体权限延续仍需在目标 macOS 验证。

## 怎样调画质和流量

连接后，在**公司 Mac 窗口工具栏的画质与连接**中修改。选择后自动应用，通常不需要断开、重新连接或停止共享：

- **最长边**：1280、1920、2560、3840 像素，以及“原分辨率（上限 8K）”。
- **帧率上限**：10、15、30、60 fps。
- **目标码率**：1、2、3、5、8、12、30、60、100 Mbps。

设置区显示所选参数与一次“已生效”确认；等待应用时另显示当前仍生效的参数。连续快速修改会合并为最新选择，等待上一项确认后再发送，避免同时调整采集与编码。切换时可能短暂停留在上一帧；新画面从关键帧开始。

成功确认的参数会随该地址和端口的连接记录保存，快捷连接和自动重连时自动恢复。家里 Mac 的“默认共享设置”仍用于每次新会话的初始值；控制端调整只影响当前会话，不修改主机保存的默认值。修改主机默认值仍需先停止共享。

对于没有已保存画质的连接，若首次有效网络往返延迟（RTT）低于 **10 ms**，新版本会默认选择最高组合：**原分辨率 / 60 fps / 100 Mbps**。已保存画质与本次手动选择优先；首次样本达到或超过 10 ms 后，后续偶尔降低的 RTT 不会突然提高画质，自动重连也不会重新选择。低于 10 ms 的延迟显示一位小数，判断使用原始数值；RTT 反映往返耗时，不能证明连接一定属于局域网。

原分辨率尽量保留显示器的实际物理像素，不放大小屏幕；为沿用解码器的边界，上限为单边 **8192 像素**、总计 **3600 万像素**，并向下取偶数尺寸。超过边界时按比例缩小。5K、6K、8K 的编码能力与实际帧率取决于 Mac 的硬件、网络和工作负载；100 Mbps 是视频目标码率，仍使用有损 H.264 / 4:2:0，不代表无损原画。ScreenCaptureKit 可以采集显示器物理像素；实际观感还受窗口缩放、显示器像素密度、H.264 量化和 4:2:0 色彩采样影响。提高码率可减轻压缩损失，但无法恢复被色彩采样丢弃的细节，60 fps 也不是清晰度或持续 60 帧的保证。

60 fps 与 60/100 Mbps 需要两端均更新；连接 0.8/0.9 共享端保留原分辨率、30 fps、30 Mbps 上限，连接更旧版本沿用旧档位。新共享端的初始消息仍携带旧端能接受的画质，额外高帧率默认值通过可选字段发送；控制端确认能力后再请求保存的或自动选择的新档位。旧控制端连接新共享端时最多沿用 3840 / 30 fps / 12 Mbps。新控制端连接旧共享端时仅显示旧选项，临时降低已保存的新档位不会抹掉原偏好；主动手动选择并确认旧档位后，才将该选择保存为新的偏好。

若调整失败，应用会显示原因并回到主机确认的实际值；恢复原配置失败或超过 25 秒未收到确认时，会关闭本次连接，由已开启的自动重连接续。两端均需 0.4.0 才能动态调节；连接旧主机时会提示升级，现有远程操作仍可用。

| 使用场景 | 最长边 | 帧率上限 | 目标码率 |
| --- | --- | --- | --- |
| 网络较窄，简单办公 | 1280 | 10 fps | 1–2 Mbps |
| 默认，代码与办公 | 1920 | 15 fps | 3 Mbps |
| 需要更清晰的代码文字 | 2560 | 15 fps | 5 Mbps |
| 较多滚动或动画 | 1920 | 30 fps | 5–8 Mbps |
| 低延迟连接，优先细节 | 原分辨率（上限 8K） | 60 fps | 60–100 Mbps |

“最长边”保留显示器比例，尺寸取偶数，不放大小分辨率屏幕。1920 指最长边，不保证所有显示器都是 1920 × 1080。右下角显示应用收发数据量与视频帧数的每秒采样值；流量包含应用消息头和剪贴板文件，不包含 TCP/TLS/IP 开销；画质设置中的码率仅针对视频。

历史流量从本版开始按远端设备累计，显示本机发送、接收与合计；同一设备更换地址或端口、断线重连和切换控制/共享角色时继续合并。每台 Mac 保存一个随机设备标识，更新应用会保留；清除应用数据后会成为新的统计设备。名称、地址和配对码不用于猜测设备身份。旧版缺少设备标识时仅保留瞬时流量，不把未知流量归入某台设备；双方升级后开始累计，旧版本消耗无法追溯。移除快捷连接及其钥匙串配对码不会删除独立保存的历史流量。

查看入口：连接页的“流量统计…”，共享页的“设备流量统计…”，以及会话画质与全屏设置中的“设备历史流量…”。

统计包含视频、控制、剪贴板、保活与应用消息头。发送按 Network.framework 成功处理的应用帧计数，接收按交付应用的字节计数；不代表对端已确认接收，不包含 TLS/TCP/IP 开销或重传，不能作为网卡或运营商计费流量。连接识别设备前的应用字节会先缓冲，识别后归入该设备，关闭后已提交发送的有效完成回调仍归入原设备。

历史在有变化时约每秒原子保存一次，断开和退出时额外保存；异常退出、写盘阻塞或磁盘错误仍可能丢失尚未落盘部分。读取或写入失败会显示原因并保留原文件，不会用空记录覆盖损坏的历史。历史与设备标识保存在本机 Application Support/QuietDesk，独立于快捷连接记录和钥匙串。

码率是编码目标，配置一秒数据率窗口，关键帧、网络开销与短时峰值会使瞬时值有所偏差。若持续发送 3 Mbps 视频，约为每小时 1.35 GB；静止画面通常远低于此。屏幕上的时钟、动画和光标也算变化。

实现使用 ScreenCaptureKit 获取画面、VideoToolbox H.264 编码与解码、AVSampleBufferDisplayLayer 显示解码画面。优先使用系统硬件编码器；系统是否实际选择硬件取决于设备与资源，功能测试记录不代表所有 Mac 都能硬件编码。

仅对系统标记为有更新的画面编码，静止时保留最后画面，不重复发送视频，连接保活仍会发送极少量数据。每个视频帧要等客户端解码确认后才提交下一帧；等待期间只保留最新采集画面，避免弱网中累计陈旧画面。已经编码的预测帧不会中途丢弃。帧率也受网络往返时间、编码和解码耗时限制；高延迟网络下可能低于设置上限。

H.264 使用有损的 4:2:0 色度采样。它适合控制动态画面的流量，但对彩色小字不保证比所有 VNC 编码更清晰，也不保证在所有静止桌面场景都更省流。请在相同分辨率和工作负载下比较实际流量与文字可读性，再决定使用参数。

## 安全与功能边界

- 连接使用系统 Network.framework 的 **TLS 1.2 / PSK / AES-128-GCM**。随机配对码提供双向密钥认证，无证书提示、无明文降级。采用此标准套件是为了兼容系统的外部预共享密钥支持。
- 该 PSK 套件**不提供前向保密**：持有码的人可连接设备；密钥日后泄露也可能影响已录制流量的保密性。不要用弱口令替代程序生成的随机码。
- 监听的是本机可用网络接口，并非仅回环地址。仅在你希望开放的端口建立映射；应用不包含 NAT 穿透、云端账号或第三方服务器。
- 首版一次共享一个所选显示器，并接受一个已认证的控制会话。已有会话期间，新会话会被关闭。可停止共享、更换显示器再连接。
- 支持鼠标移动、左右键、中键、拖动、滚轮、物理键码及修饰键。键盘布局和输入法由家里 Mac 决定。Cmd+Tab、系统级输入法切换等由本机系统截获的快捷键可能留在公司 Mac。中文输入与各类键盘布局需要在实际两台设备上验收；也可手动传送剪贴板文字后粘贴。
- 触控板和精细滚轮的小数像素会按横纵轴分别累计，避免慢速滚动被逐次取整丢失；普通鼠标的滚动倍率与方向保持原样。释放控制或断开连接时会清空尚未形成像素的余量。
- 释放焦点、切换应用和连接断开时会释放远端已按下的键和鼠标按钮。正常网络断开通常立即处理；静默断链约 30 秒由保活超时处理。编码或视频确认超过 90 秒未返回也会重建会话。
- 暂不包含音频、锁屏/登录窗口/FileVault 解锁、HDR、远程切换显示器或完整触控板手势。
- 本地临时签名版本不等同于正式签名并公证的发行版。移动应用或重新构建后，macOS 可能要求重新授予权限。正式部署建议使用自己的 Developer ID 签名与公证。

## 从源代码构建

不依赖第三方运行时包、订阅服务或完整 Xcode；需要 Apple 命令行开发工具、Swift 5.9+ 和 Python 3。

```sh
xcode-select --install
cd /你的路径/QuietDesk
chmod +x build-app.sh
./build-app.sh
```

输出是 `dist/QuietDesk.app`，默认同时包含 Apple 芯片和 Intel 两种架构。如需仅构建一种架构，使用 `./build-app.sh arm64` 或 `./build-app.sh x86_64`。如果有自己的 Developer ID，可用 `SIGNING_IDENTITY='Developer ID Application: …' ./build-app.sh` 签名；公证和发布需自行配置 Apple 账号。

应用图标位于 `Resources/QuietDesk.icns`，构建时会复制到应用包并写入图标配置，供 Finder、Dock 等位置使用。更新后若 Dock 暂时显示旧图标，请完全退出旧应用、替换后重新打开。

在 Git 仓库中构建完成后运行 `python3 scripts/package-app.py`，会在 `dist/` 生成 DMG、应用 ZIP、源码 ZIP 和 SHA-256 校验文件。DMG 内含应用与“应用程序”快捷方式，不会安装后台守护进程。源码 ZIP 带本次实际版本和构建号，解压后可直接构建应用。

## GitHub Actions 与自动版本

推送到 `main` 会执行完整检查、构建 Apple 芯片/Intel 通用应用、生成 DMG/ZIP/源码和校验文件，随后创建 `v版本号` 标签并发布 GitHub Release。PR 只检查和编译，不发布。工作流使用 GitHub 提供的令牌，发布任务仅需仓库内容写入权限；无需保存个人令牌或 Apple 证书。

- 首次发布使用 `version.json` 中的初始版本 **0.6.0**。之后按已存在的正式版本标签递增补丁号，例如 `0.6.1`、`0.6.2`。版本按数字比较，测试或打包失败时不会创建标签。
- 在 **Actions → Build and release macOS → Run workflow** 中选择 `auto`、`patch`、`minor` 或 `major`，可手动发布并控制递增级别；只允许从 `main` 发布。
- 构建号为 `version.json` 的基础构建号加该工作流的运行序号；同一次工作流重跑会复用已创建的版本标签和构建号。上传中断后可以重跑，先创建草稿、上传完整文件后再公开。
- 发布流程串行执行。发布前如 `main` 已有更新提交，旧任务保留 Actions 构建产物，由新提交的任务发布，避免旧代码成为较新的正式版本。
- 发布版本记录在标签中，本地检出对应标签会读取真实版本及构建号。`version.json` 提供无标签时的默认值及自动发布的版本下限；可以用 `QUIETDESK_VERSION=0.7.0 QUIETDESK_BUILD_NUMBER=20 ./build-app.sh` 显式构建指定版本。版本参数会校验后再写入应用。

自动发布的应用沿用临时签名，未经过 Developer ID 签名与公证；正式签名仍可通过本地 `SIGNING_IDENTITY` 配置。仓库采用 MIT 许可证。

运行自动检查：

```sh
swift run --disable-sandbox QuietDeskChecks
./scripts/run-app-checks.sh
python3 -m unittest discover -s scripts/tests -v
```

检查程序不依赖 XCTest，可以在只有命令行开发工具的环境运行。协议检查涵盖配对码、消息边界、视频包损坏、输入边界、分辨率和新增可选字段的旧版兼容；键盘检查覆盖短按/长按、重复报告、取消判断与输入源选择。网络检查只监听 `127.0.0.1`，验证加密收发、错误配对码和 TCP 分片重组；运行环境需要允许本地监听。视频检查生成合成画面，执行 H.264 编码、打包、解包及解码，还覆盖连续更换编码器时的分辨率、帧率和码率切换。其他检查覆盖动态画质请求合并、失败回复、过期回复隔离、参数与记录兼容，以及重连间隔、慢速收包、后台视频解码、文件树、有效 PNG、传输取消、并发复制、路径越界拒绝、TLS 分块传输中交错处理控制消息。文件确认检查覆盖未确认前零文件数据与零接收文件、确认后字节一致、拒绝、旧回复、请求替换、旧版元信息、重复请求、源文件变化、提前推送数据的拒绝、停止同步和文字/图片继续自动传输。检查不录制屏幕、不监听真实键盘、不读取系统剪贴板、不注入按键、不操作实际钥匙串或登录项，也不切换本机输入法。若要单独跳过网络检查，可加参数 `--skip-network`。

`run-app-checks.sh` 直接编译实际应用使用的 `ClipboardSync`，以计数的内存剪贴板和临时接收目录验证焦点禁止期间零内容读取、恢复后仅发送最新复制、已发起传输继续完成，以及文件弹窗激活、接受、拒绝和本机新复制之间的顺序。此检查不访问系统剪贴板；真实应用切换及两台 Mac 的端到端行为仍需实机验收。

## 在两台 Mac 上验收

1. 使用默认参数连接，确认屏幕、点击、输入英文代码、Cmd+C/V、修饰键组合、拖动和滚轮可用。
2. 在家里 Mac 选定中文输入法，确认实际使用的输入流程；测试 ⌃⌥Esc 和切换到本机其他应用能释放控制。
3. 分别保持静止、连续输入、快速滚动一分钟，记录右下角平均流量并比较 VNC；必要时调整分辨率和码率。
4. 按住修饰键或拖动时断开连接，确认远端不继续保持按键状态；恢复网络后手动重连。
5. 测试 Retina 缩放、实际显示器布局、屏幕锁定、唤醒和重新授权后的行为。这些依赖真实设备、权限和网络，自动检查不能替代。
6. 测试按钮、绿色窗口按钮及 ⌃⌘F 进入/退出全屏，检查右侧悬浮图标点击才展开、弹窗外关闭、远程鼠标定位与键盘释放；开启状态浮层，核对分辨率、RTT、视频 FPS、收发流量和重新打开后的开关状态。状态浮层所在位置的点击应仍传递到远端。
7. 启用 Caps Lock 后，测试短按切中英文、长按松开开启大写、短按解除大写、按住期间切换应用或断线不触发动作；分别在普通窗口与全屏操作。

8. 在真实两台 Mac 之间测试文字、截图图片、文件和文件夹复制，等待大文件完成后本机粘贴；传输中断、重新复制并取消粘贴，确认不会发布不完整文件。
   文件分别测试接收、不接收、关闭弹窗、新复制替换、等待超过约 90 秒、确认前断线及关闭同步；检查确认前的网络流量只有元信息且没有接收文件。分别在共享窗口关闭、后台、全屏情况下验证提示和焦点恢复，确认后完成下载再粘贴。
9. 在系统设置允许登录项后，退出重登或重启，确认家里 Mac 登录后最小化并自动共享，菜单栏可恢复窗口；检查停止共享后不会自行重启。
10. 首次成功连接后退出并重开客户端，确认最近连接及钥匙串快捷连接；人为断开网络后恢复，确认自动重连与主动取消。
11. 在普通窗口和全屏中分别调节最长边、帧率和码率，等待生效值更新，确认画面、鼠标定位和输入仍正常；连续快速修改后检查最终值。退出重开并快捷连接，确认恢复上次成功参数、主机默认值没有被修改。实际 ScreenCaptureKit 动态更新及失败回退仍需两台 Mac 验收。

源代码位于 `Sources/QuietDesk`（界面、采集、输入）和 `Sources/QuietDeskCore`（协议、加密连接、视频编解码）。

剪贴板与文件的状态浮层在最新消息显示约 1 秒后自动收起；后续消息会重新计时，完整状态仍可在设置中查看。文件接收确认窗口不会自动同意或拒绝，等待用户选择。

## 被控端静音与防窥

连接后从画质与连接或全屏设置进入“被控端静音与防窥”，两个开关默认关闭，仅本次连接生效。静音针对默认输出与系统提示音设备，结束后恢复原状态；设备不支持系统静音时会显示原因。会话子进程监测控制进程退出，异常结束后也会尝试恢复，不安装登录项或系统服务。设备拔出、驱动拒绝、父子进程同时结束或断电仍可能无法即时恢复。

防窥使用本地黑色窗口遮罩，并先让 ScreenCaptureKit 排除本应用，远端继续显示其余桌面。被控 Mac 可用 ⌃⌥Esc 立即退出遮罩，断线时也会撤除；注册退出键失败则不会开启遮罩。此模式无法保证遮住 Mission Control、系统安全界面等，不等同于关闭物理显示器。开启期间 QuietDesk 自身窗口也不传回，确认被控端文件或权限前请先关闭。旧版不支持这两个开关，需两端更新。

## 全屏系统快捷键

全屏并点按远程画面后，控制端通过受焦点约束的系统事件监听，将 ⌘空格、⌘Tab 等键盘组合送入原有远端键盘路径；⌘V 仍先等待剪贴板同步。⌃⌥Esc 释放控制和 ⌃⌘F 退出全屏保留在控制端。离开画面、窗口失焦、断开或权限失效时停止监听，并释放远端按键。

该能力需要控制端的辅助功能与输入监控真实生效，从“键盘设置”查看实际状态与重新检测。系统安全输入或监听被系统暂停时会显示原因，不循环重建监听。系统保留行为仍受 macOS 限制，具体快捷键与两机上的系统设置需实测。本次未增加自定义按键映射。
