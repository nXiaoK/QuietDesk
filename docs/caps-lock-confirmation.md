# Caps Lock 输入源切换确认

本次修复针对 UDP 视频下 Caps Lock 状态仍显示正在转发、切换后立即输入可能继续按原输入源处理的问题。Caps Lock 指令和键盘始终经可靠 TCP；没有把输入迁到 UDP，也没有修改原有短按、长按、焦点和权限条件。

旧流程调用 `TISSelectInputSource` 返回成功后立即回复目标输入源名称，并继续处理下一条键盘消息。该返回值只能证明选择请求被系统接受；源码没有核对实际已选输入源，也没有等待后续主线程轮次。因此此前的“切换成功”不能证明下一个输入事件已处于新输入源。

现在选择后每 20ms 查询当前输入源，连续两次与目标 ID 一致才回复“远端输入源已确认”，最多检查 25 次。等待采用异步方式，让主线程继续处理系统事件；此期间保留当前 TCP 消息的处理屏障，后续键盘消息仍按原顺序等待。普通键盘、鼠标和其他控制消息不主动增加等待。确认失败会返回提示，不重复切换输入源或模拟额外快捷键。

失去控制、断开、暂停或权限变化触发的输入释放会使在途确认失效；旧会话也不能向新会话发送成功反馈。已经发给系统的输入源选择请求无法撤销，本修复不尝试把系统输入源再切回去。输入法内部的中英文模式、密码框或应用专属输入上下文不等同于 TIS 输入源 ID，两个匹配读数仍不是实际中文字符输入的证明。

另外修正了 Caps Lock 事件监听的超时路径：系统暂时因超时关闭监听时，仅在权限仍有效且原监听恢复成功的情况下继续工作，并清除被打断的手势。用户停用、权限失效或恢复失败仍走已有停止与提示流程。

复用范围为被控端 InputSources/InputInjector、主机会话的有序消息处理器和控制端 CapsLockMonitor。协议、配对资料、文件确认、视频路径及系统权限保持原有约定。

新增检查使用替代输入源、权限查询和事件投递函数，不访问或切换真实本机输入源，不向系统注入按键。覆盖延迟激活、短暂反转、选择成功但未生效、取消和权限丢失、大小写行为，以及 UDP/TCP 视频会话下短按后紧接普通键盘的回环顺序。事件监听检查通过合成超时与 HID 值验证恢复、重复报告和焦点隔离。

这是一项针对已确认时序缺口的修复。用户报告的苹果自带拼音现象尚需真实双机复测，不能把合成输入源检查当作真实输入法验收。复测请在普通文本框中对照 UDP/TCP，短按后立即输入 `nihao`，观察候选词及首字母；长按大写开启时，短按先解除大写的旧行为仍保留。
