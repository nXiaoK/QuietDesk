# 本地即时光标

移动时出现两个清晰指针、停止后重合，通常是本机指针与视频内的远端指针叠加。视频指针必须经过采集、编码、网络、解码和显示，低 RTT 或使用 UDP 也不能消除这段跟随。

新版双方默认启用“本地即时光标”，可在普通窗口或全屏的“画质与连接”中关闭。启用后，被控端从采集画面移除光标，控制端显示本机即时指针；远端形状、热点和位置通过已认证的可靠 TCP 控制连接独立传输。UDP/TCP 视频自动选择保持原有行为。

## 切换与兼容

- Hello 的可选 `independentCursorV1` 能力与新媒体能力同时成立时才发起请求；旧端继续使用视频光标，不会收到新增消息。旧消息编号和协议版本保持不变，新增消息编号为 29–31。
- 请求串行处理，快速操作仅保留最新选择。主机先暂停媒体配置事务，再切换 `showsCursor`，清除旧采集缓存并等待配置完成后的新样本。样本同时核对递增 PTS、目标尺寸和 Mach 时钟中的 SCK displayTime，防止缓存的旧光标画面成为恢复帧。
- 每次新媒体事务在 Ready 前，通过控制连接发送该媒体流的精确光标绑定。控制端只在对应新流已经解码、生成可入队的显示样本时切换光标模式，并清除显示层保留的旧图像。候选解码完成、收到状态或显示层仍繁忙时均不提前切换。
- 会话、光标代次、媒体代次及形状/位置序号隔离旧回调和旧消息；待处理绑定、图片大小及缓存数量均有限。位置必须有限且在归一化范围内；PNG 先检查长度与尺寸，再由 ImageIO 解码。
- 暂停时保存目标模式，恢复后先应用配置并等待新帧；与画质、暂停和防窥采集调整按任务创建顺序协调。配置失败尝试恢复已确认的原模式，无法确认实际采集状态时关闭会话，按已有自动重连选择恢复。
- 首次光标请求等待新媒体流已经提交，避免媒体协商前改变旧视频的光标模式。请求 25 秒未确认时重新建立会话。采集配置和新样本等待受同一 2 秒窗口约束；回退有独立的有限等待。静止桌面能否及时产生配置后的样本仍需双机验收，超时不会假装成功。

## 输入与形状

移动消息使用单调时钟合并，目标上限为每秒 60 次，保留最新位置并定时补发停止前的最后位置。点击、拖拽、滚动和键盘边界先发出待处理移动；退出会话、失焦、权限失效或暂停会取消旧位置，避免恢复后补发过时输入。点击和拖拽沿用可靠输入协议。

被控端每秒最多采样约 30 次，只有位置或形状变化时发送。采样基于共享显示器对应的 AppKit/Quartz 坐标，不假定主显示器位于固定原点。指针离开共享显示器时不读取形状。控制端正在远程画面内操作时使用原生本机指针；其他情况下可显示独立远端位置叠层，叠层不拦截输入，也不移动本机物理指针。

系统允许时读取 `NSCursor.currentSystem` 的形状；此公开接口可能返回 nil，后续系统也可能始终无法提供。未知或无法解码时明确显示“通用指针”，不把未知解释为隐藏。图片按逻辑点尺寸及热点还原，Retina 像素不直接作为光标点尺寸。自定义、动画光标及打字时自动隐藏等行为未保证完全还原；需要原始行为时可关闭此选项。

## 验证边界

纯协议、移动调度、假光标提供者、合成图像、隔离画布以及真实 TLS/DTLS 回环检查覆盖主要边界。检查不录制真实屏幕、不注入真实输入、不修改权限、不启动生产应用。Universal 编译和安装包检查不等于 Intel 或 macOS 14 实机测试。

两台 M2/M3 Mac 的真实静态/动态桌面、Wi-Fi、缩放、全屏、多屏布局、自定义光标及更新后的系统权限仍需验收。不能以本机合成检查承诺所有应用都无拖影，或宣称已经达到其他产品的完整体验。
