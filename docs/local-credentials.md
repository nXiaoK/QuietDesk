# 配对码改用本机文件

本轮按用户选择停止使用钥匙串保存配对码，并采用手动补录旧码的迁移方式。

## 当前行为

- 不查询、添加、更新或删除旧钥匙串项目；不会自动迁移，也不需要为配对码输入 macOS 登录钥匙串密码。
- 主机码与各条远端连接的码写入 `~/Library/Application Support/QuietDesk/Credentials/pairing-codes.json`。格式版本为 1，内容为明文 JSON；目录权限 `0700`，凭据文件和锁文件权限 `0600`。这属于当前账户的文件权限保护，不是加密，同账户的程序仍可能读取。
- 原连接记录、地址、端口、名称和画质仍使用原结构。按选中的记录 UUID 保存补录后的凭据与画质；同地址多条记录不会串用，用户改地址/端口后也不会按旧 UUID 覆盖别的记录。
- 主机缺码时只显示待配置状态，不自动生成、不监听端口、不安排后台重试；自动共享偏好保留。显示和复制按钮也不会生成新码。
- 主机在共享页填入原码并点“保存原配对码”，再开启共享；也可以明确点击“生成新配对码”，此时旧码对新版主机失效。控制端点旧记录后若提示缺码，在主表单补录原码并连接，认证成功后保存。
- 删除连接仅删除新文件中的对应码和原连接记录，不碰旧钥匙串。读取失败时不会使用上一条连接残留在输入框中的码。

## 文件与失败处理

独立锁文件协调多个实例和进程，保存先写私有临时文件并同步，再在同目录原子替换；失败保留原值，不把残缺内容当作成功。目录和文件通过描述符访问，拒绝符号链接、硬链接、非普通文件和异常所有者。

损坏、非法配对码或未知版本会明确报错并保留原文件，不自动清空重建。需要恢复时按错误提示备份并移走该凭据文件，再手动补录；这不会删除旧钥匙串或连接元信息。原子替换后的目录同步尽力执行，尚未验证突然断电、网络盘、特殊 ACL 或同账户恶意替换目录。

## 验证

- 应用完整编译通过。
- `scripts/run-credential-checks.sh`：15 项通过，0 失败；独立构建的同一检查另重复 10 轮均通过。
- 覆盖主机/多连接往返、缺码不生成、明文格式及 `0700/0600` 权限、损坏/未知版本拒写、安全路径、80 个并发实例、8 个进程各 20 个账号、受控部分写失败保留原值、选中记录身份和旧 JSON 兼容。
- 测试只使用临时目录和合成配对码，不访问真实凭据文件、系统钥匙串或真实 UserDefaults。未运行生产应用、安装候选包、改系统权限或中断连接。
- 已静态检索调用链，缺码不会从共享、显示、复制或自动启动入口隐式生成；运行时 UI 的真实手动补录、重启和双机自动共享尚未实测。
- 新凭据检查加入 PR 与发布工作流；本地仅解析 YAML 和核对脚本路径，没有触发远端工作流。

网络协议、TLS 和两端配对方式不变；原配对码补录后可继续与旧端互连。本轮没有解决 TLS 1.2 PSK 的前向保密限制，也没有改变代码签名方式。
