# 自托管中继

[返回首页](../README.md) · [节点部署](../relay/README.md) · [需求与验收范围](relay-requirements.md)

两台 Mac 均主动访问同一台 Linux 节点，可以在 Mac 没有入站端口映射时连接。节点自身需要双方可达的 TCP 服务端口；同一数字端口开放 UDP 后可使用中继 UDP 视频。Mac 配对认证、桌面 TLS/DTLS 和既有文件确认仍由两端执行，节点只转发内层密文。

## 两端配置

1. 按[节点指南](../relay/README.md#docker-单命令部署推荐)用 Docker 单命令部署，或使用独立 Linux 程序。可用 `./deploy.sh --ip 服务器IP` 首次生成自签证书，无需域名；也可提供匹配 IP/域名的已有证书。Docker 首次部署会随机生成独立的 64 位十六进制节点接入码。把接入码安全交给需要使用节点的两台 Mac；不要发到诊断日志或公开仓库。
2. 在 QuietDesk 的“中继设置”启用功能，填写 `tls://relay.example.com:7443` 和节点接入码并保存。不写端口时使用 `443`；地址不能包含用户名、密码、路径或查询参数。首次必须填写接入码，同一节点后续留空表示保留。
3. 被控 Mac 开启共享，等待真实状态显示“已在中继登记”。共享面板显示的设备标识用于另一端寻址；它不是控制授权。屏幕录制、辅助功能与允许控制状态分别按实际权限显示。
4. 控制 Mac 选择“仅中继”，填入被控 Mac 的设备标识和原有 Mac 配对码后连接。仅中继不要求目标 Mac 的 IP 或入站端口映射。
5. 两端升级到支持中继的版本。接通后核对“控制路径”和“视频路径”；旧端不支持或设备标识不匹配时会明确报错。

中继接入码、Mac 配对码、本机登记密钥分别保存。节点接入码只允许使用节点；知道接入码或设备标识不能绕过 Mac 配对。客户端沿用私有凭据文件存储，不新增钥匙串操作。连接记录只保存节点、设备标识、策略和原有偏好，不包含密钥；点按记录只用记录中的节点连接，不会改变本机共享登记的节点。

停止共享或断开连接后才能修改配置。更换设备标识后，另一端需更新保存的目标；原有 Mac 配对码不随之改变。若本机登记凭据丢失，应恢复备份或使用新标识，节点会拒绝不同凭据接管已有标识。

## IP、自签证书与节点信任

服务地址可以填写 `tls://203.0.113.10:7443`；IPv6 使用 `tls://[2001:db8::10]:7443`（示例地址须换成实际服务器地址）。证书 SAN 必须包含填写的 IP 或域名，不能仅依靠 CN。两台 Mac 都需使用支持节点证书信任的版本，分别完成下列任一操作：

- **导入证书：**在服务器按节点指南导出公开的节点证书，通过可信渠道交给 Mac，在“中继设置”选择“导入节点证书…”，支持单份 PEM 或 DER 证书。不要导入私钥或整份证书链。
- **核对指纹：**在“中继设置”选择“获取并核对指纹…”，与服务器终端显示的完整 SHA-256 证书指纹逐项核对。获取动作只读取候选证书并拒绝 TLS 握手，不会发送节点接入码或登记凭据。

确认指纹后勾选“已通过服务器终端或可信渠道核对上述指纹”，点“信任此证书”，再点“保存”。导入、获取和选择证书均不立即保存；取消设置或更改服务地址会放弃未保存的候选。不要仅凭同一条未验证网络连接上显示的指纹确认服务器身份。

保存的是此节点的公开证书，按规范化后的完整地址及端口隔离，随本机应用偏好保留；不会安装到系统钥匙串或改变其他应用的证书信任。每次连接仍验证地址、有效期、服务端用途和保存证书与对端证书完全一致。登记、控制、独立 TCP 视频、数据及中继 UDP 路由协商均使用同一规则，内层 Mac TLS/DTLS 和配对规则不变。

没有保存节点证书时沿用 macOS 系统信任。已保存的证书不匹配、过期或记录损坏时会拒绝连接，不自动退回另一份证书。更换/续期自签证书后，部署者需通过可信渠道发布新指纹，两台 Mac 重新核对并保存。使用“使用系统信任”并保存可移除此地址的固定证书；其他节点的信任不受影响。关闭中继不会删除已保存的信任。

## 策略与恢复

| 选择 | 行为 |
| --- | --- |
| 仅直连 | 保留原 IP/端口方式，控制端不联系中继；旧记录缺少中继字段时使用此方式 |
| 自动（直连优先） | 先尝试已知直连地址；没有直连地址时使用中继。网络连接失败可尝试已配置的中继，配对失败不会以另一条路径绕过认证 |
| 仅中继 | 控制、独立视频和文件/自动剪贴板均经节点；UDP 不可用时回退可靠视频 |

“仅使用 TCP”仍在下次连接生效，同时跳过直连与中继 UDP。没有公共 STUN/TURN、公共节点或多节点选区；中继 UDP 视频可按[中继打洞](#中继打洞)尝试直连。

自动模式中，健康的直连 TCP 不会因为配置中继就改走节点。只有真实的可靠视频交付失败，且双方协商支持、目标标识匹配，才准备中继 UDP 候选。编码、解码或显示忙碌不构成换网络的理由。候选必须完成 DTLS 验证和实际关键帧解码，再由双方提交新流；切换期间保留旧画面，控制连接和输入所有权保持原样。

首次不同路径可在真实交付故障后试用，后续失败沿用 30/60/120/300 秒退避。UDP 探测不等于媒体可用；失败不会显示为已切换。视频连续无法经可靠路径交付时，自动模式可重建全中继连接；若这次中继回退未能接通桌面，同一目标随后的视频故障在 30/60/120/300 秒冷却内不再切换中继，直连会话继续恢复画面，经中继成功连接后冷却清零。离开已建立会话的切换按重连处理，空闲暂停期间同样延后。重建会按原流程释放输入、重新配对并取消未完成传输。已显示过画面的会话关闭“自动重连”后不会自动重建控制连接。静止、暂停和用户取消不触发这种重连；迟到结果不能恢复已取消会话。

## 中继打洞

视频经中继 UDP 时，两台 Mac 可以借助节点做 UDP 打洞，让视频直接在两台 Mac 之间传输，节省节点流量并去掉绕行节点的延迟。只有视频会直连；控制、键鼠、光标、剪贴板和文件仍经节点 TCP，所以键鼠这一程的延迟不变。控制端在“画质与连接”、被控端在共享页的“自托管中继”卡片选择：

| 选项 | 行为 |
| --- | --- |
| 自动（默认） | 打通后比较直连与中继的往返时间和丢包。直连往返超过中继往返加 max(20 ms, 30%)，或丢包持续明显更高时，视频保持中继，约 60 秒后重新评估 |
| 开 | 打通就让视频直连 |
| 关 | 不协商打洞、不交换网络地址，与之前版本相同 |

- 两端都不是“关”，且两端与节点都是支持此功能的版本时才会尝试；任一方不支持时照旧使用中继 UDP。是否换到直连由控制端决定；被控端选“关”时不会交换地址。
- 视频先经中继出画面。双方媒体 DTLS 握手并完成一次双向挑战后，各自才把本机网卡地址交给节点；节点要等双方都同意后，才把对方的地址（节点观察到的公网映射和对方的网卡地址）下发。随后两端同时向对方发送带认证的探测，控制端选用往返最短的可用路径，被控端确认后双方改走直连。切换不需要新关键帧，内层 DTLS 不变。
- 直连约 0.8 秒收不到合法封包就回到中继，中继租约在直连期间一直保活。之后按 30/60/120/300 秒退避重试；网络变化后会重新收集地址。
- 改为“关”立即回到中继；从“关”改为其他选项，在下次连接（被控端为下次开启共享）时生效。“自动”与“开”之间可随时切换。
- 打洞后两台已配对的 Mac 会互相看到对方的公网地址和网卡地址（局域网 IPv4、全局 IPv6）。只知道节点接入码或设备标识的人拿不到这些地址。
- 能否打通取决于双方 NAT。家用路由器常见的锥形 NAT 通常可以；双方都是对称型 NAT，或一方对称、另一方端口受限（部分运营商级 NAT、手机热点）时通常打不通，视频保持中继。节点 UDP 不可用或开启“仅使用 TCP”时不尝试。
- 节点必须看到客户端的真实来源地址。默认 Docker 部署（rootful、iptables 端口发布）满足；rootless Docker、userland-proxy 或会改写来源地址的负载均衡会让打洞失败，视频保持中继。
- 首次向局域网地址发送探测时，macOS 可能询问“本地网络”权限；拒绝只影响局域网地址的直连。

## 状态与排障

- “直连控制 + 中继 UDP 视频”表示只改变视频路径。“中继控制 + 中继 TCP 视频”表示全会话使用可靠中继。
- “直连 UDP 视频（中继打洞）”只在打洞路径经过认证并完成双方确认后显示；退回中继后立即恢复为“中继 UDP 视频”。打洞选项下方的状态行显示：正在尝试、已打洞直连（网卡地址 / 公网映射 / 对端映射）、中继延迟或丢包更低、未能打通或直连中断。诊断日志记录 `peerPathChanged` 的状态和候选类型，不记录地址。
- 界面 RTT 来自端到端控制消息往返；它不是可见操作延迟。内层回环 TCP 的系统测量被抑制，避免误显示为真实节点延迟。
- “目标设备未连接此中继”先核对节点、设备标识、共享是否开启以及被控端登记状态。
- “接入凭据不正确”检查节点接入码；配对失败检查 Mac 配对码。这是两层不同的认证。
- 证书错误需核对 IP/域名 SAN、证书链、有效期、已保存的节点证书或系统信任。自签证书首次须按上节导入/核对；更新证书须重新核对。客户端不会跳过证书验证或改用明文。
- 只有 TCP 可达时仍可观看和操作。若需要 UDP，检查节点同一数字端口的 UDP、防火墙、负载转发与公网映射。客户端使用配置的公网端口，不追随服务器报告的私有监听端口。
- 服务断开、重启或网络变化会使中继隧道失效；有界恢复后仍失败会提示重新连接。节点不可用不应阻断独立的仅直连连接。

文件仍逐次确认，失败清理半成品；不会增加自动接收或断点续传。输入法、Caps Lock、焦点、权限和暂停逻辑继续使用原通道。诊断只增加路径、阶段和数值，不记录节点接入码、配对码、业务内容或目标设备标识。

节点能看到连接地址、时间与流量规模。视频实际平均载荷 8 Mbps 约为每小时 3.6 GB 的单向载荷，节点另有对应入站、协议及文件开销，账单以服务商计费口径为准。打洞直连后视频不再经节点，节点仍承担控制、光标、剪贴板、文件、15 秒一次的保活，以及每秒约一次用于比较延迟的小探测。

## 验证边界

自动化检查使用本机回环、临时证书、临时私有凭据和假视频/输入接收器；不会录屏、修改真实剪贴板、注入系统输入或更改权限。它们覆盖服务鉴权、端到端 TLS/DTLS、可靠通道、UDP 阻断、私有/公网端口差异、视频故障、健康直连、解码超时、暂停、取消和输入顺序。

Linux 交叉编译与 Universal 构建不能代替 Linux 实际部署、真实双 Mac、公网丢包/抖动、Intel/macOS 14 运行和可见时延验收。当前执行结果和限制应随本地候选包的验证记录查看；不把需求中的时延目标当作实测结论。
