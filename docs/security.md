# 安全与限制

## 连接与凭据

- TCP 连接使用系统 Network.framework 的 **TLS 1.2 / PSK / AES-128-GCM**。配对码由 **256 位随机数**生成，等同于控制凭据；只应通过可信渠道传递。新版视频 UDP 使用 **DTLS 1.2 / PSK / AES-128-GCM**，在已经配对认证的 TCP 控制连接内交换每个会话独立生成的随机媒体密钥与绑定令牌；这些会话材料不写入凭据文件或日志。
- 主机配对码与快捷连接凭据改为保存在本机 `~/Library/Application Support/QuietDesk/Credentials/pairing-codes.json`。目录权限为 `0700`，文件权限为 `0600`，仅当前账户可访问；内容是明文，没有单独加密，同账户的其他进程仍可能读取。
- 应用不再查询、写入或删除钥匙串凭据。旧钥匙串条目保持不动；升级后手动补录原配对码一次，连接记录和画质偏好保留。缺少主机码时不会自动生成或开启共享，避免无提示更换原码；只有明确点击生成新码才会换码。
- 当前 PSK 套件**不提供前向保密**。配对码泄露可能使他人建立连接，也可能影响此前被记录的加密流量；停止共享后可重新生成配对码，使旧码失效。媒体使用临时会话密钥不改变这一限制，因为密钥由上述 TCP 连接交换。
- 复制配对码时使用仅限本机的剪贴板，并附加 Concealed / Transient 隐私标记；60 秒后仅在剪贴板未变化时清除。QuietDesk 的自动和手动发送都会跳过带这些敏感标记的内容。
- 局域网可直接使用被控 Mac 的 IP 和监听端口，默认数字端口为 `5908`。新版共享在同一数字端口接受 TCP、UDP；公网映射需将同一外部端口的两种协议转发到同一被控端监听端口。只有 TCP 可达时保留 TCP 路径。共享会监听本机可用网络接口，请仅开放需要的端口。应用不提供中转服务或 NAT 穿透，不依赖云账号，也不会自动配置路由器。
- 入站连接在派发到界面线程前预留认证名额，最多同时等待 4 个；同一远端地址每 10 秒最多开始 3 次认证。被控端启用中继后，经本机中继转发进入的回环连接另用一组最多同时等待 4 个的名额，不再按 `127.0.0.1` 共用每 10 秒 3 次的限额。已有控制会话时，新入站认证等待缩短为 5 秒。这只限制握手资源，不替代系统防火墙。
- 独立 TCP 视频和文件通道按 ALPN 角色与当前控制会话绑定；UDP 通过系统 DTLS 完成加密认证。媒体封装还核对会话、传输代次、编码代次、帧身份与分片边界，缓存、修复次数和接收队列均有限。过期参考链通过新关键帧恢复，旧会话或旧代次的回调不得提交当前画面。更多实现与验证边界见 [UDP/TCP 传输说明](udp-tcp-transport.md)。

## 权限、输入与文件

- 被控端需屏幕录制权限才能共享，需辅助功能权限才能接收键鼠控制。控制端的 Caps Lock 与全屏系统快捷键捕获还需本机辅助功能和输入监控权限。权限由用户在 macOS 中授予，以应用检测到的实际状态为准。UDP/TCP 自动传输不新增系统权限要求，键鼠与会话控制始终走可靠 TCP。
- 独立光标按能力协商，通过现有加密控制连接传输有尺寸限制的形状和归一化位置；离开共享显示器时不读取形状，不移动控制端物理指针。形状缺失时使用通用箭头，不推断系统光标可见性，不新增授权请求。边界见 [独立光标说明](independent-cursor.md)。
- 全屏且远程画面聚焦、权限生效时，⌘空格、⌘Tab 等组合转发到远端；普通窗口、安全输入或系统保留行为仍受 macOS 限制。**⌃⌥Esc 释放控制、⌃⌘F 退出全屏、⌃⌘S 截取远端画面保留在控制端**；离焦、断开或权限失效时释放远端按键。
- 文件和文件夹需要接收方逐次确认，确认前只发送元信息；下载前检查接收卷可用空间，后续写入失败仍取消并清理半成品。暂不支持符号链接等特殊文件，也不支持断点续传。
- 新版未完成数据放在带进程租约的独立目录；同步初始化时只清理能独占租约的崩溃残留，保留其他活跃实例和旧版无租约目录。已经接收的文件继续由用户在接收目录中管理，不自动删除。
- 自动文字同步上限为 16 MiB，图片为 64 MiB；超过后提示保存为文件再复制。系统剪贴板访问仍在主线程，图像转换与网络分块在后台处理。

## 本机效果与功能边界

- 防窥使用**软件黑色窗口遮罩**，不等同于关闭物理显示器，不能保证遮住 Mission Control 或系统安全界面。被控 Mac 可按 **⌃⌥Esc** 退出，断开时撤除；控制端记住的防窥会在下次连接时再次开启。开启时只从远端画面排除遮罩窗口本身（按窗口编号排除，先以近乎透明的状态放置、排除生效后才变为全黑），被控端 QuietDesk 的主窗口、菜单栏、文件确认和权限提示在远端仍可见、可操作。遮罩窗口不向系统声明为不透明窗口（看起来仍是全黑），避免系统把下面的窗口判定为被遮挡，浏览器和 Electron 应用因此停止绘制、远端画面冻结；这一点尚未在实机上确认。防窥与画质、暂停、光标的采集调整按请求顺序依次执行，防窥不会中断正在进行的光标切换。
- 断开后锁屏由被控端在控制连接结束时发起：优先调用系统锁屏入口，不可用时用辅助功能发送 ⌃⌘Q，并读取系统锁屏状态确认。任何断开都会锁屏；之后需重新连接并在锁屏界面输入密码，这一重连情形尚未实机验收，睡眠、注销、重启后无法远程解锁；强制结束、崩溃或断电时不会锁屏。系统锁屏入口不是公开接口，未来 macOS 可能改变，届时依赖 ⌃⌘Q 回退和锁屏状态确认。
- 内建屏幕亮度归零通过系统私有框架 DisplayServices（与亮度键同一路径）把笔记本内建屏幕亮度设为 0：背光关闭但显示器不睡眠，屏幕采集照常，只作用于内建屏幕，外接显示器不变暗。只有被控端有内置电池、内建屏幕点亮且系统报告可调亮度时才可用。开启前记下原亮度并启动恢复子进程；QuietDesk 崩溃或被强制结束时由子进程恢复（刚请求了断开锁屏时先等待锁屏，最多约 4 秒）。控制进程与子进程同时结束、断电或系统崩溃时，亮度可能保持为 0，可在本机按亮度键调亮。只在亮度仍为 0 时恢复，不覆盖本机用户之后的调节；本机调高亮度（含自动亮度）即视为退出，开关关闭并通知控制端，不会再压回 0。私有接口未来可能改变，接口缺失时开关不可用，不显示未生效的状态。
- 连接后自动解锁：控制端把按连接记录保存的锁屏密码经端到端加密的控制通道发给被控端，密码与保存时的配对码指纹绑定，只经用同一配对码认证的会话发送，连接记录被改指向另一台 Mac 时不会发出；记住防窥时须先确认遮罩开启，记住亮度归零且被控端可调亮度时须先确认亮度已归零。被控端同一时间只处理一个解锁请求，只在本会话锁屏且位于显示器时逐字输入，每个字符前重新确认锁屏，输入期间忽略控制端键盘输入，结束后不保留密码，日志只记录请求与结果。密码与配对码一样以明文保存在控制端仅当前账户可读的私有文件中（单独的 `session-secrets.json`），未使用钥匙串；控制端账户文件泄露时，持有者可借此解锁被控 Mac。密码限制为 1–128 个可打印字符，拒绝回车、Tab、Esc 等控制字符。
- 会话静音作用于默认输出与系统提示音设备，结束后尝试恢复原状态。设备移除、驱动拒绝、控制进程与恢复子进程同时结束或断电，仍可能使恢复失败或延迟；此功能不传输远端音频。
- 当前共享单个显示器并接受一个控制会话。不支持登录窗口（注销或重启后 QuietDesk 未运行）中的远程控制、FileVault 解锁、HDR、远程切换显示器及完整触控板手势；已登录会话锁屏后的显示与输入尚未完整验收。画面使用有损 **H.264 / 4:2:0**，原分辨率、高码率和 60 fps 不代表无损画质或保证持续帧率。

## 应用内更新

更新源是 GitHub Release 的固定资产 `QuietDesk-update.json`，不调用 GitHub REST API。仓库中的公钥表为空时，更新器不启用。启用后，首次征得自动检查选择；只在用户要求后下载，并在安装前再次确认。正在被远程控制的 Mac 禁止安装，避免更新后的本机重新授权使远程失联。

清单以 Ed25519 签名，签名覆盖域分隔前缀 `QuietDesk-update-v1\n` 和原始 payload 字节。客户端在验签通过后才解析 payload，检查应用标识、三段版本及递增 build；未知签名密钥、无效签名或异常字段会被拒绝，不能用旧清单降级。支持多个公钥供分阶段轮换；高于已知 schema 的可信清单仅提供手动更新入口。

正式更新的初始清单和 ZIP 地址限定为配置仓库的 GitHub Release，归档重定向只允许 HTTPS。客户端不提供修改更新源或镜像设置；HTTP 回环地址仅允许在独立 bundle ID 的测试构建中使用。清单不超过 64 KiB，ZIP 不超过 64 MiB，并核对实际大小与清单中的 SHA-256。说明仅显示纯文本，不执行 HTML、Markdown 或网页脚本。

解压前检查 ZIP 结构，解压后只接受一个 `QuietDesk.app`，拒绝符号链接、异常硬链接和特殊文件。新包的标识、版本、build、最低系统、可执行文件和本机架构必须通过检查，代码签名采用严格、全部架构和嵌套代码校验；当前应用有 Team ID 时，新包必须相同。临时签名仅证明包内容与其代码签名一致，更新真实性依靠内置 Ed25519 公钥与签名清单中的归档摘要。

安装在同卷暂存后由独立安装模式进程等待原进程退出，再换名替换整个应用包。安装前再次校验，替换或安装后校验失败会尝试回滚；无法确认重启时保留备份，不将备份清理等同于成功启动。目录不可写、只读卷、Translocation 或“App 管理”阻止时转为手动安装，不请求管理员提权，不授予或重置隐私权限。更新目录为当前账户私有目录，安装计划为私有文件；更新不读取或改写连接记录与配对码。

该机制防范下载链路或 Release 资产被篡改、归档不匹配及降级重放；不能防范同账户恶意程序，或具有仓库写权限且能使用发布 secret 的攻击者。私钥不得提交、打包或输出到日志，应由维护者离线备份。正式密钥配置、丢失及轮换方式见 [开发指南](development.md#更新签名与发布)。

## 兼容与签名

- 涉及对端的新功能按能力协商启用，旧端缺少能力时沿用兼容选项。UDP/TCP 新媒体、软件遮罩、会话静音、空闲暂停和新增画质档位需两端支持，建议双方更新。新版辅助通道不可用时可以在控制 TCP 内使用新媒体封装；旧端继续使用原视频消息格式。
- 仓库默认构建与自动发布使用临时签名，**未经过 Apple 公证；每次更新后都需要在本机重新授予屏幕录制、辅助功能和输入监控权限**。系统设置中的勾选不代表当前进程实际生效。本地使用固定证书签名也不等于完成 Developer ID 分发与公证，不能保证跨版本、路径或系统更新后保留隐私授权；授权是否生效仍以 macOS 的实际检测为准。

## 自托管中继

中继是额外的网络路径，不是控制授权。外层服务 TLS 按系统信任验证域名和证书，32 字节节点接入码仅允许使用节点；两台 Mac 仍需原有配对码完成内层桌面 TLS/DTLS。节点不获得桌面密钥，无法解密视频、键鼠、剪贴板或文件，但可以观察地址、时间与流量规模。

设备标识由独立登记凭据绑定，节点持久化其摘要并拒绝接管；在线令牌、单次隧道与 UDP 路由均有用途、期限和资源边界。UDP 使用分角色 HMAC、方向校验和有界重放窗口，只有新鲜合法封包可以更新 NAT 端点。客户端仅访问明确配置的节点；不会根据远端 Hello 指定任意服务器。

[中继打洞](relay.md#中继打洞)只在双方媒体 DTLS 通过桌面认证后交换地址，只持有节点接入码或设备标识的人无法获得 Mac 的网络地址；打洞后两台已配对的 Mac 会互相看到对方的公网地址和网卡地址，可在设置中选“关”。直连封包用媒体会话密钥派生的密钥认证，节点无法伪造；探测只发往节点下发的有限候选，每次尝试约 5 秒、约每秒 20 个小包，只回复通过认证的探测，不能被用作反射放大。

Mac 的节点接入码和登记凭据沿用私有凭据文件，保存的连接 JSON 不含密钥；节点证书、私钥、接入码和设备状态均在仓库与分发包之外。部署、备份、升级和日志边界见 [节点指南](../relay/README.md)。
