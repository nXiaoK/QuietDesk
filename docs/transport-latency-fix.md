# 视频传输延迟：TCP 确认策略修复

## 本轮改动

修复版为 0.6.5 / build 14，基于 build 13 的诊断结果。已确认大视频消息在发送和完整接收期间反复等待数百毫秒，收到后解码通常只有几毫秒；具体 TCP 缺口、窗口或系统网络栈触发原因尚未唯一确认。

本轮只调整一个影响因素：应用的监听端和连接端显式开启 `NWProtocolTCP.Options.disableAckStretching`。Apple 公开 SDK 将它定义为每两个数据包发送确认，目的是避免 ACK stretching；它不是每包立即 ACK，也不表示关闭所有 delayed ACK。

该策略可能增加确认包数量，换取更及时的反馈。真实无线链路、不同系统版本下的吞吐和延迟变化仍需实测，不能仅凭设置成功推断收益。

`SecureTransport.parameters` 由应用和检查程序复用。新增 `responsiveAcknowledgements` 参数默认 `false`，通用调用保留原有配置，QuietDesk 应用两端显式传 `true`。参数在连接创建前设置，监听器接收的连接继承该配置；不修改系统全局 TCP 设置。

TLS 配对认证、Wire 消息编号/字节格式、H.264 参数、画质偏好、三帧窗口、剪贴板流程、重连及失败处理均保持原逻辑。它是本机 TCP 行为选项，不需要新增应用层协议协商；新设置可以和旧设置端互连。旧版二进制实机互连仍需验收，不能仅凭源码默认配置的回环检查声称所有旧版本已实测。

连接就绪日志新增 `tcpAckStretchingDisabled`，从实际 `NWConnection.parameters` 的 TCP 选项读回：1 表示配置已开启，0 表示未开启，无法读取则不写该值。这个字段证明参数配置，不等于抓包证实了系统每个 ACK 的实际时机。

## 为什么没有同时改其他参数

在合成回环实验中，将 280 KiB 消息改为 32 KiB 分次写入并没有消除有序接收的等待；人为延后尾段 120 ms 后，两种方式都需要等尾段。直接在旧视频消息体中插入心跳会破坏旧协议；独立心跳通道也不能自动修复画面停顿。因此本轮保留原写入和流控方式，避免把更小的每次写入耗时误当完整视频已经更快。

视频侧实验也没有获得可靠的关键帧硬上限：本机 100 ms 码率窗设置成功但仍输出超过该窗口字节预算的关键帧；slice 大小和零帧延迟设置不受当前编码器支持。低延迟编码模式能降低部分合成编码耗时，但首个关键帧可能变大，且编码器选择与 GOP 行为变化，未作为本次传输故障修复一并启用。

以上离线实验没有复现用户网络上的 0.6–1.1 秒长尾，不能把其亚毫秒差异当作实机收益。本轮是针对确认等待的最小修复候选，真实改善需由同场景的 build 13 / build 14 对照确认。

## 复测方法

1. 在方便断开时，两端退出旧版，再使用 build 14；不要同时运行两份应用。本轮没有覆盖或启动已安装应用。
2. 保持之前复现问题的 1920 / 30 fps / 8 Mbps，在两端顶部菜单栏右侧的双显示器图标菜单中开启「性能诊断」。
3. 播放相同视频约 2 分钟，记录是否还有明显停顿，再从两端导出诊断日志。
4. 核对连接日志的 build 14、源码版本和 `tcpAckStretchingDisabled: 1`。重点比较视频 `receiveBody`、`videoAck` 长尾、完成帧数和实际流畅度；只有心跳 RTT 降低不能判定画面问题解决。

日志分析命令和计时边界见 [性能诊断](performance-diagnostics.md)。编码/解码/发送/接收窗口部分重叠，不能相加或跨端直接相减时间；缺少性能样本不能当零耗时。

本包沿用 ad-hoc 临时签名，未公证。重新签名后系统可能要求确认原有权限，本轮没有授予或重置系统权限。回退时可使用此前的 build 13 包，保存的连接信息和配对码不因这个 TCP 选项变更而迁移。

## 本次验证

- 核心回归 134 项通过，包含新增 4 项确认策略检查：默认保持关闭、启用后读回正确，以及新旧两种设置的两个混合方向和双端启用组合。
- 三个 TLS 组合均验证 256–280 KiB 合成视频消息、256 KiB 剪贴板类二进制载荷、应用帧 ACK 和双端心跳，消息字节、顺序及序号保持一致。接受连接实际继承监听器选项，主动连接读回选项也与设置一致。
- 上述是协议字节和配置验证，不是实际系统剪贴板、真实画面或旧版应用二进制的端到端测试。原有认证错误、断开、重连、视频和文件等核心检查一并通过。
- arm64、x86_64 Release 编译与 Universal 合并通过；两架构最低系统均为 macOS 14.0。Info.plist 和 ad-hoc 签名检查通过。
- 独立差异审查与 `git diff --check` 通过。没有启动或中断用户生产连接，没有读取真实剪贴板、钥匙串或更改权限，没有推送或发布。
