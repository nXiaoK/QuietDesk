# Windows 版

QuietDesk for Windows 让 Mac 可以远程控制 Windows 电脑，也让 Windows 电脑可以远程控制 Mac。它是独立的原生 Win32 程序（Rust 编写，单个 `QuietDesk.exe`，不需要安装运行库），与 macOS 版使用同一套配对码和基线协议，旧版 macOS 客户端仍可配对并使用原有功能。两端均升级后，向任一方向复制的文件都在接收端粘贴时开始传输。

> 第一版已在 Windows 被控端试用。此次更新的独立光标、控制连接上的媒体会话及编码器启动延迟仍待 Windows 10/11 实机确认。

## 获取

```sh
./scripts/build-windows.sh
```

在 macOS 上生成 `outputs/windows/QuietDesk-<版本>-Windows-x64.zip`（内含 `QuietDesk.exe` 与许可证）及其 SHA-256。首次构建会下载并校验固定版本的 llvm-mingw。构建 Opus 需要 CMake 3.16 或更高版本；缺少时脚本会把经校验的 CMake 3.31.10 Universal 也缓存到 `work/toolchains/`。程序面向 Windows 10 / 11 x64，只依赖系统自带的库；未做代码签名，首次运行时 SmartScreen 可能提示“未知发布者”。

## Mac 控制 Windows

1. 在 Windows 上运行 `QuietDesk.exe`，在“共享这台电脑”中点“开始共享”。首次共享会生成配对码；Windows 防火墙询问时请允许访问。
2. 在 Mac 的 QuietDesk 中填写这台电脑的地址、端口（默认 `5908`）和配对码后连接，与连接另一台 Mac 的步骤相同。

Windows 主窗口的“共享屏幕”默认跟随主显示器，也可以选择具体屏幕。这个选择会保存在本机。控制端在会话内切到另一屏只影响本次连接。选中的屏幕断开时，支持切屏的两端会更新可用列表并切到可用屏幕。

Mac 键盘的修饰键可在 Windows 端“Mac 键盘”中选择：

| 选项 | ⌘ | ⌃ | ⌥ | 右 ⌘ |
| --- | --- | --- | --- | --- |
| ⌘ 与 ⌃ 都作为 Ctrl（默认） | Ctrl | Ctrl | Alt | Win 键 |
| 标准 | Win 键 | Ctrl | Alt | Win 键 |

默认选项让 `⌘C`、`⌘V` 等 Mac 习惯直接对应 `Ctrl+C`、`Ctrl+V`。其余按键按键位对应，字符由 Windows 当前的键盘布局决定。Mac 上的 F13 / F14 / F15 对应 Print Screen / Scroll Lock / Pause。

Windows 能读取当前桌面的键盘大写状态时，可在 Mac 控制端开启 Caps Lock 独立转发。短按会在松开时向 Windows 发送 `Win+空格` 切换到下一输入法。若远端大写已开启，短按会先关闭大写。按住至少 0.6 秒再松开会切换远端大写。多个输入法可能共用一个键盘布局，如果窗口提示已发送快捷键，请在远端确认当前输入法，并按提示点击输入位置。

## Windows 控制 Mac

1. 在被控 Mac 上按原有步骤开启共享并复制配对码。
2. 在 Windows 的“控制另一台电脑”中填写地址、端口和配对码后点“连接”。连接成功后会记入“最近连接”，配对码用当前 Windows 账户加密保存（DPAPI）。

连接成功后，“最近连接”显示被控端的名称。同一台设备换地址或端口时，Windows 会在设备 UUID 和本次配对码都相同的情况下更新原记录。旧版被控端仍按地址和端口匹配。

被控端支持切屏时，远程窗口的“显示器”菜单会列出可用屏幕、主屏标记和分辨率。切屏期间会释放键鼠控制，等新屏的画面显示后即可继续操作。切换失败时，窗口会显示原因。

PC 键盘的修饰键可在“键盘”中选择：

| 选项 | Ctrl | Alt | Win 键 |
| --- | --- | --- | --- |
| 标准（默认，与 Apple 对 PC 键盘的约定一致） | ⌃ | ⌥ | ⌘ |
| 左 Ctrl 作为 ⌘ | 左 Ctrl 为 ⌘，右 Ctrl 仍为 ⌃ | ⌥ | ⌘ |

远程窗口获得键盘焦点后，`Alt+Tab`、Win 键等系统快捷键也会发往 Mac。`Ctrl+Alt+Enter` 切换全屏，`Ctrl+Alt+Esc` 释放控制，点击画面可继续。窗口菜单可发送或获取剪贴板文字、切换画质和断开连接。

在远程窗口的“会话”菜单勾选“独立转发 Caps Lock”，即可短按切换远端输入法、长按切换远端大写。菜单默认关闭，选择会作为新窗口的默认值。窗口标题会显示被控端回报的结果。失去焦点、暂停或撤回控制时会取消尚未松开的按压。

游戏和 3D 软件可在“会话”菜单开启“相对鼠标”。点击远端画面后，Windows 会锁定本机指针，把鼠标移动量发给被控端。按 `Ctrl+Alt+Esc` 或切换到其他窗口即可释放，重新点击画面可再次锁定。旧版被控端使用常规指针。

使用精密触控板时，远程窗口可按像素传递双指滚动及惯性。被控端支持手势时，还可传递捏合缩放。提供 Windows 触摸手势的设备可传递旋转和双指点按。Mac 控制 Windows 时，缩放、旋转和智能缩放在共享屏幕的前台应用内转换为双指触摸，实际效果取决于应用的触摸支持。

主窗口的“断线后自动重连”默认开启。网络中断时，远程窗口保留最后一帧，标题显示第几次重试和剩余时间。可以在窗口中点“立即重试”或“取消重连”。重新连接后沿用上次选择的画质。配对码错误、自己断开或收到被控端主动结束通知时，会话结束。

远程窗口最小化时立即暂停画面。窗口连续十分钟处于后台也会暂停，返回窗口时恢复。暂停传输需要被控端支持会话暂停。

## 远端系统声音

Mac 控制 Windows 时，在 Mac 会话中选择“开启远端声音”。Windows 控制 Mac 时，在远程窗口的“会话”菜单勾选“播放远端系统声音”。Windows 每个新窗口默认关闭声音。同一窗口自动重连后会恢复此前开启的声音。

Windows 被控端采集默认输出设备正在播放的系统声音。Windows 控制端将声音送到本机默认输出设备。暂停会话会停止采集或播放。声音设备不可用时，窗口会提示原因，视频会话可以继续。真实声卡、蓝牙耳机和长时间播放的延迟仍待 Windows 实机验证。

## 双向剪贴板

在 Windows 被控端勾选“允许同步剪贴板文字、图片和文件”。Windows 作为控制端时，在远程窗口的“会话”菜单勾选“自动同步剪贴板”。Mac 端需开启双向剪贴板。

1. 复制文件或文件夹。两端都支持延迟文件粘贴时，复制只通告有文件可粘贴。打开粘贴菜单或查看可用格式时不会传输文件。
2. 在接收端粘贴。应用读取文件格式后，QuietDesk 才向发送端索取文件清单。接收端会显示名称预览、项目数和总大小。确认接收后开始传送文件内容。
3. 等待接收完成。如果第一次粘贴已返回，请在目标文件夹再次粘贴。Windows 接收目录是 `%LOCALAPPDATA%\QuietDesk\Clipboard\received`，Mac 接收目录是 `~/Library/Application Support/QuietDesk/Clipboard/received`。

支持辅助 TCP 通道时，文件清单和已批准的内容通过独立加密连接传输。复制、粘贴和接收确认的操作与使用控制连接时相同。

同一份文件连续请求只发起一次传输。关闭同步、撤回复制或拒绝接收会使等待中的请求失效。旧端按已协商的剪贴板能力工作，Windows 远程窗口也可手动发送或获取文字。

## 这一版包含与不包含

| 包含 | 说明 |
| --- | --- |
| 配对与加密 | 与 macOS 版相同的 TLS 1.2 / PSK / AES-128-GCM，配对码通用 |
| 画面 | 两端验证同一端口的加密 UDP 可双向通信后，通过它传输 H.264 视频并补传丢失的分片。UDP 不通时改走独立 TCP 视频连接，必要时使用控制连接。每次切换都等首个关键帧解码，旧端仍可使用原视频协议 |
| 声音 | 经配对的控制连接传输 48 kHz 双声道 Opus。Windows 两个角色都支持远端声音开关、暂停恢复和有限丢包补偿 |
| 光标 | 两端都支持时，Windows 控制端在首个视频流提交后请求独立光标。操作画面时本机显示远端指针形状；仅观看时在画面上叠加远端位置。连接旧版或协商失败时沿用实际的采集模式 |
| 显示器 | 可选择本机共享的屏幕，或通过远程窗口切换对端屏幕。协议最多列出 16 个活动显示器 |
| 画质 | 控制端可调分辨率、帧率（最高 60 fps）与码率；Windows 被控端另有“画质上限” |
| 键鼠 | 键盘、鼠标移动/点击/拖拽/双击、滚轮与触控板滚动、侧键；失去焦点时释放按键 |
| 其他 | 断线自动重连、空闲暂停、被控端结束通知、允许控制开关即时生效 |
| 剪贴板 | 手动文字、按需文字和图片、经接收端确认的双向文件粘贴 |

暂不包含（对端提供时也不会启用）：视频前向纠错、自托管中继、HEVC、端口映射、模拟键入、自动解锁、黑屏遮罩与静音、应用内更新。

这些功能的实施顺序、协议依据与验收方法见 [Windows 版后续实施方案](windows-plan.md)。

Windows 被控端的已知限制：

- 每次共享一个显示器。选中的显示器旋转或桌面复制不可用时改用 GDI 采集，占用更高。旧控制端在被控端切屏时可能需要重新连接。
- 独立 Caps Lock 转发要求 Windows 当前用户能读取活动控制台键盘的大写指示。无键盘、驱动拒绝查询、不同键盘指示不一致或处于远程桌面会话时，连接沿用常规键盘行为。
- 相对鼠标在 Windows 单屏或游戏已将指针限制在共享屏时保留原始移动量。普通多屏桌面会将落点限制在共享屏内。如果本地用户将指针移到另一屏，远端的新移动、点击和滚轮会暂停。将指针移回共享屏，或退出相对模式后重新定位即可恢复。
- 以当前用户身份运行：UAC 提示、锁屏和以管理员身份运行的窗口无法被控制，出现这些界面时画面会暂停更新。
- 缩放与色彩转换在 CPU 上进行，使用系统自带的软件 H.264 编码器；4K 屏幕缩小后 60 fps 可能达不到，实际帧率会自动降低。
- Windows N / KN 版需先安装“媒体功能包”，否则没有 H.264 编解码器。

## 日志

`%LOCALAPPDATA%\QuietDesk\logs\quietdesk*.log`（按大小轮转，保留 3 份）。日志不记录配对码、地址、剪贴板内容或按键。设置保存在 `%APPDATA%\QuietDesk\settings.json`。本机设备 UUID 独立保存在 `%LOCALAPPDATA%\QuietDesk\device-identity.json`。身份文件不可用时可照常配对和连接。

共享画面时，日志中每秒的 `host video stats` 给出采集方式、等待画面变化的时间、实际抓屏、转换和编码的平均耗时。`output` 是编码器返回给采集线程的帧数，`queued` 是进入发送队列的帧数，`dropped` 是采集线程未能送入队列的编码帧数。`process_cpu_ms_per_s` 是整个进程每秒使用的 CPU 毫秒数，1000 相当于占满一个逻辑核心。某项没有样本时显示 `na`。

## 检查

```sh
./scripts/run-windows-interop-checks.sh   # Windows 端协议代码 ↔ macOS 实现，回环 TLS，双向
./scripts/run-windows-wine-checks.sh      # Windows 可执行文件在 Wine 容器中的冒烟检查，需要 Docker
```

- 互通检查用 Windows 协议代码对接 macOS 的 `Peer`、VideoToolbox、`MediaSession`、`ClipboardTransfer` 和光标协议实现，覆盖双向建流、视频内容、确认窗口、画质切换、暂停恢复及旧版兼容。合成光标用于核对透明像素、逻辑尺寸、热点、位置和生效时机。
- Wine 检查运行 Windows 可执行文件，覆盖 GDI 采集、Media Foundation 编解码、原生光标像素和热点，以及 Windows 双端互连。独立 OLE 测试还覆盖文件格式枚举、读取、确认、拒绝和本机复制覆盖。Wine 使用虚拟桌面和 GStreamer，系统编码器和显卡驱动的实际表现须在 Windows 上验证。

## 实机验收

用 Mac 控制 Windows，再用 Windows 控制 Mac。每个方向先确认静止桌面有首帧，再打开会持续变化的窗口、切换一次分辨率、暂停并恢复，确认画面都能继续更新。

- Mac 控制 Windows 时，在 Windows 日志中查找 `host committed udp media stream`。使用 TCP 时，提交记录的路径为 `tcp` 或 `shared`。首个关键帧日志里的 `after 1 captured frames` 可用于核对编码器启动时机。
- Windows 控制 Mac 时，查找 `viewer committed udp media stream` 或该次使用的 TCP 路径。两个方向都应在建流、分辨率切换和恢复后看到对应角色的提交记录，后两次记录里的代次应递增。
- 用 Mac 控制 Windows，在文本框、链接和窗口边缘之间移动鼠标，确认只看到一个跟手的指针，形状和点击热点随上下文变化。反向连接时，在 Windows 的 100%、150%、200% 缩放下复查热点，并在释放控制、指针移出画面、暂停和恢复后检查远端指针位置。
- 用 Windows 连接 Mac，选择画质后临时中断网络再恢复。观察同一窗口中的倒计时和恢复后的画质，再分别验证“立即重试”、取消、主窗口关闭自动重连和被控端主动结束。
- 两端各试一次主屏切换到外接屏，再拔掉当前外接屏。将外接屏放在主屏左侧或上方，核对实际画面、光标位置及点击目标。分辨率相同的双屏也应显示各自的内容。

- 在 Finder 和资源管理器之间各复制一次带空文件、中文文件名和子文件夹的目录，先查看粘贴菜单，再粘贴并确认接收。核对内容和文件数。用大文件再试一次，在等待时复制新的本地内容，确认两边提示与最终剪贴板归属。

以下只能在真实 Windows 电脑上确认：桌面复制采集与光标绘制、系统 H.264 编码器的低延迟与按需关键帧、解码与 Direct2D 显示、`SendInput` 键鼠与高 DPI/多显示器坐标、键盘钩子与全屏、防火墙提示、DPAPI 读写、界面在不同缩放比例下的排版，以及两个方向的实际延迟与帧率。
